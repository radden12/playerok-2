# Playerok KOSell Clean Bot

Минимальный Telegram-бот для автоматической продажи аренд KOSell на Playerok. Проект написан с чистого листа: в `/start` только две кнопки — вход в KOSell-плагин и управление плагинами.

## Что уже встроено

- загрузка/обновление/удаление `.py`-плагинов прямо в Telegram;
- постоянное хранение плагинов, настроек, связок и JPEG в `/app/data` на Bothost;
- импорт сначала 10 игр, затем 100 или всего каталога;
- слоты 1, 2, 3, 7, 14 и 30 дней в пределах доступности KOSell;
- для ограниченных категорий Playerok сроки 14/30 дней передаются атрибутом `168`, но название, описание, цена и фактическая аренда сохраняют 336/720 часов;
- цена с учётом комиссии Playerok, минимальной цены и обязательной прибыли;
- физическая загрузка JPEG: исходная обложка KOSell, безопасная версия и запасная обложка без текста;
- проверка вложения до и после публикации, а затем периодический контроль отложенной модерации;
- выдача логина/пароля только после статуса сделки `PAID`;
- очередь при отсутствии аккаунта или баланса KOSell;
- ответ Steam Guard на точное слово `код` или `code` до окончания аренды;
- удаление только тех объявлений Playerok, которые связаны с этим плагином.

## 1. Создание Telegram-бота

1. Откройте `@BotFather` в Telegram.
2. Выполните `/newbot`, задайте имя и username.
3. Скопируйте токен — это `BOT_TOKEN`.
4. Узнайте свой числовой Telegram ID через `@userinfobot` — это `ADMIN_ID`.

## 2. Доступ к Playerok

Playerok не выдаёт этому проекту отдельный API-ключ. `PlayerokAPI` работает через cookies вашей авторизованной браузерной сессии.

1. Войдите в `https://playerok.com` в Chrome.
2. Нажмите `F12` → **Application** → **Storage** → **Cookies** → `https://playerok.com`.
3. Скопируйте как минимум `token`, а при наличии защиты также `__ddg5_`.
4. Создайте строку вида `token=ЗНАЧЕНИЕ; __ddg5_=ЗНАЧЕНИЕ`.
5. После запуска бот запросит только Cookie, сам подставит технический User-Agent, проверит вход в Playerok и только после успешной проверки сохранит подключение в `/app/data/playerok_connection.json`.

Никому не отправляйте Cookie и не добавляйте его в GitHub: Cookie даёт доступ к аккаунту. Бот удаляет сообщение с Cookie сразу после чтения. Если Playerok покажет проверку браузера после переезда на Bothost, откройте в плагине кнопку **Playerok** и подключите сессию заново.

Перед массовым импортом вручную создайте один черновик в нужной категории `Игра → Аренда` и примите правила категории, если Playerok их показывает. В PlayerokAPI есть чтение непринятых соглашений, но нет метода их принятия; плагин сообщит точный каталог, где требуется ручное действие.

## 3. API KOSell

Получите API-ключ в личном кабинете KOSell согласно документации `https://ru.kosell.store/api/docs`. При первом входе в плагин бот сам попросит ключ, удалит сообщение после чтения, проверит ключ запросом баланса и только затем сохранит его в `/app/data/plugin_data/kosell-playerok-clean-v1/state.json`.

## 4. Новый репозиторий GitHub

1. Создайте пустой публичный репозиторий без README и `.gitignore`.
2. Распакуйте этот архив и загрузите в корень репозитория все файлы.
3. Убедитесь, что в корне видны `Dockerfile`, `requirements.txt` и `run.py`.
4. Не загружайте `.env` и реальные cookies/API-ключи.

Публичность важна для простого клонирования Bothost. Ошибка `could not read Username for 'https://github.com'` означает, что репозиторий приватный либо URL/доступ настроены неверно; это происходит до чтения `requirements.txt`.

## 5. Развёртывание на Bothost

1. Создайте Python/Docker-бота из нового публичного GitHub-репозитория и ветки `main`.
2. Добавьте переменные окружения:

   - `BOT_TOKEN` — токен BotFather;
   - `ADMIN_ID` — ваш числовой Telegram ID.

   Больше никаких переменных указывать не нужно. Cookie Playerok и API-ключ KOSell бот запросит в Telegram.

3. Включите постоянное хранилище Bothost. Проект сам создаст внутри `/app/data`:

   - `plugins/` — установленные плагины;
   - `playerok_connection.json` — подключение Playerok;
   - `plugin_data/kosell-playerok-clean-v1/state.json` — настройки, связки, заказы и аренды;
   - `plugin_data/kosell-playerok-clean-v1/images/` — физические JPEG для Playerok.

4. Соберите и запустите контейнер. В логе должна появиться строка `Бот запущен`.
5. Напишите боту `/start`. На экране должны быть ровно две кнопки.

## 6. Безопасный первый запуск

1. Откройте **KOSell → Playerok**.
2. Пришлите запрошенный ботом Cookie Playerok. После проверки бот автоматически перейдёт к настройке KOSell.
3. Пришлите API-ключ KOSell. Он будет сохранён только после успешной проверки.
4. Проверьте настройки цены. По умолчанию прибыль `+10%`, комиссия Playerok `20%`, минимум `90 ₽`.
5. При необходимости измените название, описание и сообщения покупателю. Поддерживаются фигурные скобки, перечисленные на экране настройки.
6. Нажмите **Старт** → **Сначала 10 игр**.
7. Дождитесь уведомления по каждой игре вида `✅ Игра [Название]: создано слотов 6/6` и итогового отчёта.
8. Откройте объявления Playerok и визуально проверьте категорию, срок, цену и картинку.
9. После успешных 10 игр запускайте 100, затем весь каталог.

Playerok модерирует изображения независимо от загрузки. Поэтому наличие картинки в ответе API не гарантирует, что она не будет запрещена позднее. Плагин проверяет `isAttachmentsForbidden` и автоматически меняет исходную картинку на безопасную. Если Playerok отклонит даже обложку без текста, бот пришлёт честное уведомление — программно обойти решение модерации нельзя.

## 7. Обновление или удаление плагина

Откройте вторую кнопку `/start`: **Плагины: добавить / удалить**.

- **Добавить или обновить**: отправьте `.py`. Совпадающий `UUID` автоматически заменит старую версию.
- **Удалить**: удаляется файл плагина и бот перезапускается; его данные в `/app/data` сохраняются для следующей версии.
- **Удалить все связки и объявления** находится внутри KOSell-плагина. Эта команда удаляет только сохранённые в нём ID объявлений Playerok.

## Локальная проверка

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python run.py
```

`run.py` читает из окружения только `BOT_TOKEN` и `ADMIN_ID`; файл `.env` автоматически не загружается и приведён только как локальный шаблон этих двух значений.
